# 26.47.0

## Highlights

- **Device sync rebuilt:** pair devices on the same network, then sync the whole catalog (one device's catalog is kept) or collections only. Each collection's owner allows None, Preview, Serve or Sync; other devices take None, Previews, Full Quality or Full Sync. Photos, originals or previews and their edits travel; pills on grid cells and collection rows show where each photo lives and which way changes still travel. Same app version on both devices; LAN only.

## Develop and masking

- **Masking:** hovering, clicking, or dragging a mask or component pin while Brush, Color Range, or Object is active interacts with and moves the pin instead of painting over it, and releasing a brush stroke updates the mask overlay without a one-frame delay (issue #1161).
- **Depth tile in Create New Mask:** Depth Range masks were only in Tools ▸ Create New Mask; the Masks panel and its Add / Subtract / Intersect menus now offer Depth after Color. Without Depth Anything V2 Small it opens Settings ▸ AI Models for the download and makes no empty mask. Thanks @RalfKerkhoff for the report (issue #1144).

## Develop

- **Tool profiles:** Settings ▸ Develop customises the Develop panel's sliders. The built-in Default (every group) and Witchcraft (Primaries and HSL Curves, Eboda's Color Grading hidden) profiles can't be changed; your own can be added, duplicated, renamed and deleted, switch any group off, hide single sliders and options, and hold one Custom group of chosen sliders in a chosen order. A low row at the top of the panel picks the profile, with a gear to Settings ▸ Develop; `view.toolProfile` and `view.toolProfileEdit` do the same for scripts and agents. Stored profiles naming sliders a later build doesn't know keep the rest.
- **Tidier panel head:** Browse Profiles joined Edit, Crop and Remove in the tool row; the profile row and the Edit title line are gone, and Auto · B&W | HDR open the Basic group.

## Library

- **Which face a tile is about:** People's face close-ups (unnamed faces, a person's faces and suggestions) outline their own face, and hovering one shows the whole photo with that face marked, so a tile with two people in it no longer leaves you guessing whom you are naming. Thanks @pokemonbattledroid for the idea (issue #1147).
- **Filter by "no colour label":** the filter bar's colour-label swatches gain a hollow one at the end that shows only the photos without a label, ANDing with the chosen colours (issue #1192). The Library menu's Filter by Color Label submenu has a matching No Label row, the text search takes `label:none`, and the `library.filter` command takes `labelsNone`. The MCP `query_photos` tool's filter description now names the real filter keys (`rating` with `ratingOp` for the at-least, exactly and at-most comparisons, `labels`, `labelsNone`) instead of a `minRating` example that the filter rejects.
- **A cleaner full-screen preview:** `I` cycled to Off now clears the photo of all text: the shot-info strip under the photo (ending in the pixel size) goes with the file information and stays hidden from photo to photo until the overlay comes back. `G` leaves the preview for the grid you chose, and every view or module switch (grid style, Detail, Loupe, Compare, Survey, Reference, People, module picker) leaves the preview instead of changing the view hidden underneath; `Esc` and `F` are unchanged.
- **Face and search indexing controls:** Recognise faces is off by default (installing or downloading a model no longer switches it on; a library where it was on keeps it). Settings ▸ Faces and Settings ▸ AI Models ▸ Semantic search show the face scan's and search indexing's progress with Pause / Resume (kept across restarts), Clear… and Restart…, which ask first; their activity rows get a pause button and a gear that opens the right Settings page. Semantic search can be switched off, which stops its indexing and hides the AI search button. New commands: `faces.status`, `faces.pause`, `faces.resume`, `faces.clearIndex`, `faces.restart`, `ml.indexStatus`, `ml.pause`, `ml.resume`, `ml.clearIndex`, `ml.restart`, `activity.pause`.
- **Preview builds queue behind a running build:** a Build Standard-Sized / 1:1 or Smart Previews request made while another build runs is no longer refused — it waits for its turn and starts by itself when the running build ends (identical waiting requests are not queued twice; a runaway queue is capped at 16). Stop Building Previews stops the running build and drops the waiting ones. The full-screen preview (F) now shows the running tasks as a quiet card top right, using the same activity stack. PR #1208.
- **Sharp thumbnails of tight crops:** a cropped photo's grid thumbnail was cut from the 512 px thumbnail source and stretched, so tight crops came out blurry. Past a 2x stretch it now reads the preview-level source at the size the crop needs (never the original), without pushing the loupe's preview out of memory; blurry thumbnails cached before render again. Issue #1197.

## Import

- **Capture One develop settings:** the Capture One catalog import brings each variant's exposure, crop and its aspect, orientation and straighten angle, flips and white balance (Capture One's change from as shot, an approximation, marked as such for raws edited on the relative white balance scale); every other setting a photo uses is named in the result window per Capture One tool with its photo count, and photos are dated at their last change in Capture One where the catalog records it.
- **Moves to an SMB share on macOS:** moving photos into a folder on a share no longer keeps every original with "Operation not supported", and imports can make new folders there. PR #1225.
- **Work on browsed photos without importing them:** Develop, Print, Export and Slideshow chosen from the Browse tab (module picker, shortcuts, File ▸ Export…) open on the selected photo in place, and from a browsed photo in Develop, Print and Export no longer jump back to Browse; a file already in the library opens as its catalog photo. The Browse bar's buttons are now Import and Develop, without the duplicate Photo Grid / Grid / Detail switch.

## Interface

## Performance

- **Progress while the catalog opens:** the launch no longer opens the catalog before the window's first frame — a blank, silent window on a large catalog, or one an update left in an older format, made it look like the app wouldn't start (user report). A small **Opening your catalog** window shows while a worker prepares the library; the format bump after an update (its byte-verified backup copy) reports its phase and copied bytes through the same progress channel as the v3 → v4 migration, and the copy now reports byte progress on that path too. A worker that stops without an answer turns into the usual problem window instead of a dead end (also for the migration window). New strings in every language for the opening window.
- **Plug-in filter stacks no longer slow down with every filter added:** a stack with a filter that reads neighbouring pixels (a degrain, a sharpen) runs at the photo's full resolution once per edit, shared by the loupe, the preview, the grid's cell and an export (before, each ran it, all at once, and decodes of different sizes each ran their own), and a filter added at the end, or a change to the last filter, runs only that filter on what the filters before it made. A render that is replaced (a slider drag starting, the loupe moving to another photo) stops its plug-in filters where they are. On a 10 MP scan with a negative conversion and a degrain, adding the third and fourth filters went from 119 s and 154 s to 63 s and 66 s, and an edit after adding one from 12 s to under 1 s.

## Updater and security

- **Windows updates relaunch the app and keep Start-menu shortcuts working:** installing an update on Windows now runs a small helper that waits for the app to quit, runs the installer (so it no longer overlaps the running app), and starts the app again when the installer succeeds — exit 3010 (success with a reboot required) starts nothing, because Windows starts the desktop again after the reboot. The Start-menu shortcut the installer writes is a plain link to the installed program instead of an advertised shortcut: advertisements resolve through their product's registration, which every upgrade replaces, so Start-menu entries and taskbar pins stopped working after updates. Windows CI now packages a second, higher-version MSI, upgrades over the first on a real Windows and checks the shortcut resolves.

## Fixes

- **Plug-in filters no longer fail at a fuel slice:** filter modules are compiled when loaded, as plug-in modules already are, instead of function by function as they first run. A first run that fell at the end of one of the host's fuel slices failed the band with "instruction budget", and with bands in parallel that changed from run to run (#1200).
- **Immich sync no longer loses edits or collections:** a run the server cut short records only what it really sent (the rest goes out with the next run instead of being overwritten by Immich's older values or having its keywords removed); a photo edited during a run keeps Immich's change for the next run; a failed or refused album add never removes photos from the collection (the app now reads Immich's per-photo answer); a collection that holds photos Immich does not have is never deleted for an Immich-side album delete (kept, unlinked, reported); each catalog has its own sync state and link cursor; a cleared location or capture time is not pulled back; a deletion undone in Immich leaves the queue and is never applied; "Newest wins" uses the edit time from an up-to-date XMP sidecar.
- **Immich linking and import:** photos imported after the link pass are looked up on the server by checksum and linked, Settings ▸ Connections has a Full Link Pass, the scheduled sync links too, and importing from an Immich album links and adds the photos the catalog already had.
- **Immich in Settings ▸ Connections:** server calls run in the background with an activity row (external libraries, locked folders, rescan, people, Preview Changes, which now lists its result in the Sync section); link, import and original downloads can be stopped and a failed download is reported; Disconnect and the delete buttons ask first.
- **Folder import includes its sub-folders:** browsing a folder for the first time (Import tab, Local, `library.browse`) now starts with sub-folders included — only the import review did before, so a folder picked from the Import tab browsed flat and its sub-folders' photos never made it into the import — and the Import tab's bar gained the **Include subfolders** checkbox the review and the Local folder header already have, which re-browses the folder at once. Re-browsing the same folder keeps the choice; a different folder starts over with sub-folders in.

## Development

- **Stamped manifests are read and checked:** `plugin.inspectFile` reads a stamped plug-in's `photo-plugin.manifest` section without running the module, and says so (`source: "section"`, `verified: false`); `verify: true`, and every file without a section, still read `lcc_manifest` (`source: "export"`, `verified: true`). Installing, updating or starting a plug-in whose section differs from `lcc_manifest` is refused, naming the fields that differ. The install dialog lists `lcc_manifest`'s permissions, as before.
- **Stamped plug-in manifests:** `plugin-stamp` (`sdk/stamp`), a small program for plug-in authors, runs a plug-in's `lcc_manifest` once in a sandbox and copies its answer into the `.wasm` as a `photo-plugin.manifest` custom section, so tools can read a plug-in's id, version and permissions without running it. `plugin-stamp --check` fails a build whose section is missing or stale. Nothing changes for plug-ins that aren't stamped. See "Stamping your plug-in" in `docs/plugins.md`.

## Film

- A film scanner's RGBI TIFF (four 16-bit samples, no ExtraSamples, written by VueScan or SilverFast) decodes as opaque RGB with the infrared pass as `Decoded::infrared` (and `SourceInfo::infrared`, through the geometry with `render_plane`), no longer as RGBA.
- Infrared dust removal from that pass (`FilmDust` in the develop settings: controls `filmDust.remove`, `filmDust.sensitivity`, `filmDust.expand`, Section Sensor): a Source-stage step before the plug-in filters fills the marked pixels in from their surroundings and puts the film's grain back (`lcc_pipeline::film_dust::inpaint`). The map (`infrared_map`) measures each pixel's dip in grain widths against the pass's own level with the dips left out, joins a speck's soft edge to its core, finds faint lines by averaging along strokes in twelve directions, and grows round; the picture's leak into the pass is taken out first, the red channel's dips measured the same way subtracted in the proportion fitted on detail brighter than its surroundings (`reference`, `red_of`); it is cached per pass and settings and keyed into the stage caches. `Overlay::Infrared` (the pass in grey, the marks red) and `Overlay::FilmDust` (the marks, white on black); renders with the step or these views take the CPU pipeline (`film_dust::needs_cpu`).
- `spot.filmDustMask {sensitivity, expand}` (Remove ▸ Edit as Mask) stores the marks as an Object mask (a `SegMask` over the uncropped frame, named "Film dust (infrared)", replaced on a re-run, selected) for the brush and `spot.fromMask`. `spot.findFilmDust` (heal spots on the marks; without the pass, a search of the picture) is a command only: the Remove panel shows no film-dust button for a scan without the pass.

## Sync

- **Device sync keys photos by the SHA-1 of the original:** the same checksum Immich reports, so a device with the file and a device with only an Immich link-only photo agree on the photo. Photos not hashed yet keep their content-hash key until the SHA-1 is known; their record and collection memberships then move to the new key (`Replica::rekey`), and replicas made before this change migrate when the catalog opens. A photo arriving from another device is looked up on connected Immich servers by checksum, so it is linked rather than uploaded twice.
- **Immich albums as device-sync collections:** `immich.collections` lists an account's albums as collections `immich:<user id>:<album id>` under an "Immich" set (grant fixed at Sync). Each device takes None, Previews (link-only) or Full Quality (originals) from Immich; members come from the server on each device, records travel between devices, and a photo added on any device is checked by checksum and uploaded at most once. Device sync names the account by Immich's user id, so devices reaching one server by different URLs share it. A link-only photo whose original is later imported from disk takes the file instead of becoming a second photo.
- **Shared or private Immich connections:** `immich.share` sends an account and its API key to the group's devices over the encrypted peer channel, into their key storage (never the replica, logs or results); a private account's collections are never told to other devices.
- **Camera roll collection:** `sync.cameraRoll` watches a folder (on Android, the camera roll the app already lists) and keeps a device-owned collection `Camera Roll - {Device Name}` that follows renames; photo identity by SHA-1 keeps it free of duplicates with the Immich app's uploads.
- **Removed the name-matching Immich album rule** (`immich.linkAlbum`, `immich.syncAlbums`, `immich.resolveAlbumDeletion`, Sync… ▸ Collections ↔ albums): replaced by Immich albums as collections; an account with the rule on is migrated to `collections: true`.
