# 26.48.0

## Highlights

- **Getting Started guide:** after the first welcome, a paged guide offers each AI feature's download with its size, licence, memory use and speed (pre-ticked by the computer's memory and graphics card; faces and search never; nothing downloads before Finish, then through each feature's own download command in the background), the layout, appearance, colour scheme, text size, language and grading mode (applied at once, with undo), key settings (library at launch, update checks, XMP sidecars, Reduce motion) and a short tour of the modules. Skip or Esc downloads nothing. Help ▸ Getting Started… (`app.gettingStarted`) opens it again.
- **Plug-in Marketplace:** File ▸ Plug-ins ▸ Plug-in Marketplace… lists plug-ins and pixel filters to search, install, update and remove, from an index rebuilt hourly from each plug-in's newest release (no versions pinned in the app). Entries are Vetted (a maintainer read the source) or Community (automatic checks only, hidden until asked for), and each shows the systems it supports, what it may ask for and who signed it before anything is downloaded. A download installs only when it is the file the index names; automatic updates are opt-in and install only what asks for nothing new and is signed as the installed version. Commands: `marketplace.list`, `marketplace.refresh`, `marketplace.install`, `marketplace.updateAll`, `marketplace.setCommunity`, `marketplace.setAutoUpdate`, `marketplace.autoUpdate`. The first entries are ChromaKode Film, ChromaGate and ChromaLab by @AudiFormer and Edit in DxO PureRAW by @clydecbrown.

## Develop

- **Plug-in filter source and draft metadata:** pixel filter plug-ins now receive `source` (origin, bits per sample, float) and `draft` status (including draft scale and native canvas dimensions) in their `_image` parameters, allowing filters to identify untagged linear scans and adapt during interactive slider drags. Issue #1211.
- **Fixed:** a photo whose camera make and model is absurdly long (thousands of words) no longer freezes the app while camera colour and white-balance data are looked up (#1308).
- **Changed:** process V10 applies the Tone Curve (point and region curves, Refine Saturation) in ProPhoto primaries with gamma 1.8 before the output conversion instead of on the output's sRGB-encoded values; Lightroom channel-curve edits match better and no longer depend on the export colour space. Brightness and Levels move with it, still before the curve (#1142).
- **Fixed:** clicking a histogram clipping triangle to turn Show Clipping off left the clipping mask on the photo while the pointer stayed on the triangle; the click now ends the hover preview until the pointer leaves (#1348).
- **Fixed:** Sony ILCE-1, Canon EOS 90D, Nikon Z 6, Nikon Z 8, Fujifilm X-T5 / X-T50 and Olympus E-M1 Mark II raws fell back to a neutral colour matrix; they now use LibRaw's matrices (#451).

## Library

- **Auto Import retries unfinished copies:** a file tried while it was still being copied in is tried again once its
  size changes, and an Auto Import that can't start leaves its files for the next scan (#1302).
- **Damaged library settings are kept and reported:** a `catalog-settings.json` that doesn't parse is set aside, a
  new library's settings (backups on) stand in, and a notice says so when the library opens; one that can't be read
  is never overwritten. `recent-catalogs.json` is handled the same way.
- **Folder polling finds new folders:** folders that hold only other folders are now watched for new subfolders, from
  the folder the library's photos branch out of downwards, so photos another app files into new dated folders are
  found by the next poll; a folder whose subfolders are mostly not the library's (a home folder) is not watched.
- **New:** `photo.sharedMeta` reports each Info field's shared value across the selected photos, or that it is mixed, for scripts, MCP clients and plug-ins.

## Interface

- **Shortcuts wait while a dialog is open:** on macOS, menu shortcuts such as ⌘=, ⌘- and ⌘Delete no longer act on the photo behind Settings or another dialog, and the menu bar's commands are greyed out until it closes (⌘Q still quits, ⌘W still closes the window). A key that closes the module's key list (⌘/ or Ctrl+/) no longer also runs that key's shortcut. Issue #1369, PR #1370.
- **Shortcuts wait behind every window that waits for you:** keys no longer act on the photos behind Find Duplicates, Review Comments, Import Warnings, the Plug-in Manager and the Plug-in Marketplace with their questions, Edit In Presets and the Edit Photo question, Tethered Capture Settings, the Identity Plate Editor, the catalog dialogs, the catalog chooser opened over a library, the Export sheet, the camera roll question, the questions about sharing a new collection with your other devices and uploading an edited version to Immich again, or a quit or settings-file notice. Holding `\` no longer shows the Before view behind them, or while typing. Clicks on the app behind them wait too, and on Android Back closes Find Duplicates, Review Comments, Import Warnings and the Identity Plate Editor instead of acting on what's behind them. On macOS the menu bar's commands are greyed out until it closes (⌘Q still quits). The Welcome window and the window of a catalog that couldn't be opened leave the menu bar working. In the Plug-in Marketplace, the Plug-in Manager and the Edit In windows, Esc in a text field leaves the field first. Esc (and Back) closes Tethered Capture Settings and the Immich question as their ✕ does, and puts the new-collection question off as Decide Later. Actions, Roles and Live View stay beside the photos, keys and all.
- **Fixed:** with no photo selected, the "No photo selected" line in the Versions and History panels touched the left edge of the window; it now has the margins of the panels' rows (#1385).

## Performance

- **Faster end of a Lightroom import:** looking a camera up by name in the camera database and the spectral-sensitivity table no longer normalises every row on every call; both use a hash index built once, with identical answers (a test compares the index with the old scan on every row, alias, make and model spelling it can build). The window freeze while an imported catalog is added to the library drops by about 75% (400 Nikon Z9 photos: 2.8 s to 0.7 s, measured alternating with the previous build on one machine). Part of issue #1303.
- **Lightroom catalog import commits first (#1303):** the catalog's photos are committed from the catalog alone, each
  without its original read (no content hash); the originals are then read in the background in batches of 500 (one
  stoppable **Reading originals** activity, resumed when the library next opens) and fill in the content hash, file
  facts, lens data and as-shot white balance as Reload would. New engine command `library.readOriginals` and
  `library.importLightroom` parameter `readOriginalsLater`. Records made from the catalog alone now get the import
  defaults and an upright size.
- **Publishing from a large library:** a publish built one copy of the library's originals index per photo and kept them all until the run ended, so memory and time grew with photos x library size (a 10,000-photo publish from a 10,000-photo library passed 50 GB before sending anything). A run now builds the index once and shares it, as export does (#1375). Thanks @blwfish.

## Release builds and CI

- **One program for the app and the CLI:** the desktop packages carry one build of the engine instead of two. The CLI
  is a link to the app's executable on macOS (inside the bundle), Linux (tarball, `.deb`, `.rpm`, AppImage, Flatpak),
  FreeBSD and Nix, and a small console launcher on Windows; started under the CLI's name (or with `--cli` first) the
  app's executable runs the CLI and nothing of the app. Installations are about 170 to 250 MB smaller per
  architecture, and the CLI's commands, output and exit codes are unchanged.

## Fixes

- **No abort at launch on a busy GPU:** when the window's surface failed its first configure (Metal: "Failed to wait for GPU to come idle"), the first frame asked the unconfigured surface for a texture and wgpu panicked inside a callback that can't unwind, so the app aborted during startup. The window now configures the surface again before each frame, skips frames until a configure succeeds, and never asks an unconfigured surface for a texture.
- **Pixel Shift: shot count from the mode byte:** the Nikon Z 8 writes 16 in the maker-note tag that Pixel Shift read as the shot count in every pixel-shift mode, so in 26.47.3 the first 16 frames of a 32-shot series were accepted and merged as a 16-shot series (a wrong image), and 4- and 8-shot series were refused with unrelated messages ("frame 5 is missing", "no frame number"). The mode is now read from its own byte, and a series of 4, 8 or 32 shots, or any frames of one, is refused with "n-shot pixel-shift series are not supported yet"; frames of different modes are refused as different shot counts, and a lone frame as not a pixel-shift frame. 16-shot series are unchanged.

## Metadata

- **Sidecar keywords survive Save Metadata to File:** keywords only an unsynced sidecar had are added to the photo
  and kept in the file instead of being replaced by the library's list (#1310).

## Device sync

- **Changes stamped in the future are held back:** a synced change more than five minutes ahead of this device's
  clock waits (field by field, kept across restarts) until it is due, and a notice names the device whose clock is
  wrong, so a wrong clock can't win every later conflict.

## Map

- **Fixed:** Auto-Tag from Tracklog ignored the camera time zone for photos that record their own zone (Exif `OffsetTimeOriginal`); the zone you give now reads the camera clock in that zone, matching what Set Offset from Active Photo measures (#1276).
- **Fixed:** a photo whose capture time can't be placed in the given time zone is skipped and counted (`skipped.unplaceable`) instead of failing the whole Auto-Tag batch.

## Camera colour

- **Changed:** one ranked order decides where a raw's starting colour comes from (your default, your `.dcp`, a Lightroom calibration, the file's matrices, measured matrices, the camera-JPEG fit, estimated colour); `calibrate-lightroom fit` keeps a calibration that loses to the per-photo JPEG fit but beats the plain colour as the default for files with their own colour matrices only (`ownMatrixOnly`, converted DNGs) (#1119).
- **Fixed:** the Profile section's Calibrated camera colour row and the hot-pixel count line stay laid out (pending) while a photo is decoded, so the Develop panel no longer jumps between photos (#1272).
- **Fixed:** DNGs with an embedded profile that has a look table but no tone curve (Lightroom "Adobe Standard" conversions) rendered about 0.3 EV darker than Lightroom; they now get their `BaselineExposure` once more, shown as `defaultExposure` in `photo.sourceReport` (#1174).
