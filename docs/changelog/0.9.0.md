# 0.9.0

0.9.0 includes everything in [0.9.0-rc1](0.9.0-rc1.md) (all changes since 0.8.2, upstream through its batch 40),
plus the changes below, made since the release candidate. After each fork item, the matching upstream pull request:
`(↑ #n)` means the maintainer of this fork opened it upstream, `(⇠ #n)` means it was ported from an open upstream PR,
and `(no PR)` means there is none (the change is in the fork's own Classic layout, its updater, or a fork issue with
no upstream counterpart).

> [!IMPORTANT]
> As in 0.9.0-rc1, the catalog format is version 12: 0.9.0 opens older catalogs and upgrades them, and 0.8.x can't
> open a catalog once 0.9.0 has saved it. Back up your library before upgrading from 0.8.x.

## Highlights

- **Updates are safer and opt-in:** the start-up update check is off until you turn it on, updates come only from
  this project's own GitHub releases over https, macOS installs in place with rollback, AppImage updates wait for
  the app to quit, and a Linux copy that wasn't installed from an AppImage is no longer sent an AppImage.
  Thanks @clydecbrown and @endthestart. (no PR: the fork's own updater)
- **Lightroom catalogs over 1 GiB import**, read a page at a time and cancellable. Thanks @jeanspector. (⇠ #1819)
- **Tone Curve's parametric graph you can drag**, drawn from the renderer's own curve, with the Point Curve preset
  shown on it. Thanks @deunderscorepaul and @endthestart. (no PR: Classic's curve panel)
- **Oldest first:** the grid sorts by capture date oldest first by default, as Lightroom Classic does. Thanks
  @endthestart. (no PR: Classic default)

## Develop and masking

- **Tone Curve, parametric graph:** it draws the curve the renderer applies, dragging on the graph moves the
  region sliders with it, and the graph is a clean curve. Thanks @deunderscorepaul. Fork #151. (no PR)
- **Point Curve preset in the parametric graph:** the chosen Point Curve preset is drawn on the parametric
  curve. Thanks @endthestart. Fork #166. (no PR)
- **Optics defaults for new photos:** Develop ▸ Optics can set its lens corrections as the default for photos
  imported from now on. Thanks @deunderscorepaul. Fork #148. (no PR)
- **Edit ▸ Edit Watermarks…** opens the watermark editor from the menu, as in Lightroom Classic. Thanks
  @deunderscorepaul. Fork #117. (no PR)

## Import, export and formats

- **Lightroom catalogs over 1 GiB import:** the catalog is read from disk a page at a time instead of being loaded
  whole, its write-ahead log is checked and indexed without holding its pages, and inspection or import can be
  cancelled at any point. Large develop, history and metadata tables still stream row by row, so neither a big file
  nor a big table has to fit in memory. A catalog that Lightroom changes during the read is refused rather than
  half-imported. Thanks @jeanspector. (⇠ #1819)

## Updater and security

- **The start-up update check is opt-in:** it is off until it is turned on in Settings ▸ General, the welcome
  dialog or the update dialog, and headless and in-memory sessions never check at start. A settings file that
  can't be written is reported instead of logged. Thanks @clydecbrown. (no PR)
- **macOS updates install in place:** the new version is copied beside the app and swapped in with renames, the
  old one is put back if any step fails, and a copy that isn't inside an app bundle no longer replaces the one in
  `/Applications`. No Terminal window or automation permission is involved. Thanks @clydecbrown. (no PR)
- **Updates come only from this repository's releases:** the update check no longer takes another feed from a
  command, files are taken only from the repository's own GitHub release downloads over https, and the
  `<PREFIX>_UPDATE_URL` setting, documented but never read, is gone. Thanks @clydecbrown. (no PR)
- **No AppImage for other Linux installs:** a copy that wasn't installed from an AppImage is told to update the way
  it was installed (package manager or the releases page) instead of downloading an AppImage it can't use. Thanks
  @endthestart. Fork #145. (no PR)
- **AppImage updates wait for the app to quit:** the new version starts only after the old one has exited (30 s
  at most), the swap script is written to a private folder, and the previous AppImage is deleted on the next
  start. Thanks @clydecbrown. (no PR)
- **Update error messages** no longer say "could not" twice. Thanks @clydecbrown. (no PR)
