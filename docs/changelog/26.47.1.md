# 26.47.1

## Interface

- **Settings in the Modern Shortcuts menu:** the ☰ menu's Shortcuts sheet on touch layouts gains a **Settings…** row below Import and Export, opening the same screen as Edit ▸ Settings (`app.settings`).

## Release builds and CI

- **The macOS command-line tool is inside the app, with one copy of the fonts:** the CLI is now in the app bundle (`Contents/MacOS`), signed with the app and replaced by its updates, and the separate CLI `.zip` download is gone. The craft-fonts faces (Chinese, Japanese, Korean, Arabic, Hebrew, Thai and more) are files in `Contents/Resources/fonts/`, read by both programs, instead of being built into each binary: one copy instead of four in the universal download. A missing or damaged font file is left out and named in a notice in the app and a warning from the CLI; the rest still load. The CLI inside the app never installs updates itself. The manual's Install page shows how to link the CLI onto `PATH`.

## Fixed

- Android: "Sync this device's camera roll" did nothing unless Settings ▸ Folders' Watch for new photos was also on; it now turns the watch on.
- Android: opening a 200 MP photo made the system close the app (out of memory). A photo too big to decode whole within the memory budget is decoded at a half, a quarter or an eighth of its size for the loupe and the crop view, and is not decoded ahead of a zoom; exports and CLI renders still read it whole.
- Android: Semantic search (background AI indexing) was on by default; it is now off until switched on, and an installed search model is not loaded at startup while search is off (on every platform).
- Android: the background preview build decoded each photo whole even for a standard preview, two photos at a time; it now reads each only as large as its preview needs, and builds one photo at a time under a small memory budget.
- Touch layout: a tap on a photo in the grid sometimes opened the photo opened last; it now opens the photo under the finger.
- Android: editing while previews were built in the background could still run out of memory. On a phone (a memory budget under 4 GiB) previews are now built only while browsing: entering Develop stops the build, drops what browsing held and returns freed memory to the system at once; the build resumes back in the Library. Freed memory is also returned after every decode, as on the desktop.

## Changed

- Sync onboarding simplified: Settings ▸ Sync's collections are one row each with the choice at the right (phone-width safe), Immich albums fold under one line, and each device's unfiled row names the device. The Immich account card keeps Sync Now, Import…, Choose Albums… and Metadata Sync… in view and puts the rest under More; "Show Immich albums as collections" is now "Sync Immich albums".
- The camera roll's import review adds in place only and offers "Keep adding new photos from the camera roll".
- Android: the Library's title opens a list of sources and collections.
