## Sync

- **Device sync keys photos by the SHA-1 of the original:** the same checksum Immich reports, so a device with the file and a device with only an Immich link-only photo agree on the photo. Photos not hashed yet keep their content-hash key until the SHA-1 is known; their record and collection memberships then move to the new key (`Replica::rekey`), and replicas made before this change migrate when the catalog opens. A photo arriving from another device is looked up on connected Immich servers by checksum, so it is linked rather than uploaded twice.
- **Immich albums as device-sync collections:** `immich.collections` lists an account's albums as collections `immich:<user id>:<album id>` under an "Immich" set (grant fixed at Sync). Each device takes None, Previews (link-only) or Full Quality (originals) from Immich; members come from the server on each device, records travel between devices, and a photo added on any device is checked by checksum and uploaded at most once. Device sync names the account by Immich's user id, so devices reaching one server by different URLs share it. A link-only photo whose original is later imported from disk takes the file instead of becoming a second photo.
- **Shared or private Immich connections:** `immich.share` sends an account and its API key to the group's devices over the encrypted peer channel, into their key storage (never the replica, logs or results); a private account's collections are never told to other devices.
- **Camera roll collection:** `sync.cameraRoll` watches a folder (on Android, the camera roll the app already lists) and keeps a device-owned collection `Camera Roll - {Device Name}` that follows renames; photo identity by SHA-1 keeps it free of duplicates with the Immich app's uploads.
