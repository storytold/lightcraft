- **Plug-in Manager**: **File ▸ Plug-ins ▸ Plug-in Manager…** installs, enables and configures plug-ins. Drop a `.wasm` file on it, or **Install from File…**.
- **Sandbox**: a plug-in runs as WebAssembly and can only do what you grant it.
- **Permissions are asked at run time**: installing grants nothing (the install dialog only lists what a plug-in may ask for). The first command that needs a permission shows a prompt: **Allow** runs the command again, **Deny** is remembered.
- **Who signed it**: the install dialog says who signed a plug-in, by its author key's fingerprint (four groups of four characters), or that nobody did. When an update is signed by the same key as the installed version, it says "the same author as the installed version". When it's signed by another key, or not signed, over a signed one, the dialog names both and asks: **Install Anyway** is your yes, and only you can give it (`plugin.install` takes `acceptSigner` or `acceptUnsigned`). A file whose signature doesn't hold up can't be installed, and the dialog says why. At start-up, a plug-in whose file no longer matches its signer isn't loaded; its page says why, and its permissions and data are kept.
- **Nobody to ask**: from the command line, an agent, a background job or a hook, a call that needs a permission is refused and says to allow it in the Plug-in Manager. Only you allow; commands and agents can only take permissions away.
- **Permissions tab**: each request as allowed, denied, not asked yet or refused, with **Allow** and **Revoke** (`plugin.revoke` takes one permission away).
- **Updates keep the previous version**: **Go Back to Version X** on the plug-in's page (`plugin.rollback`) restores it with its settings. If the kept version's file is no longer signed as it was when it was replaced, going back is refused and says why; install that version by hand to choose whether to trust it (`plugin.rollback` takes `acceptSigner` or `acceptUnsigned`).
- **Updates from the author**: a signed plug-in whose author publishes an update feed has **Check for updates** on its page, off until you turn it on. Then opening the Plug-in Manager checks its feed, at most once a day; nothing checks while the Plug-in Manager is closed, and **Check Now** checks at once. An update found shows its version, the author's short note, a **Changelog** link and the permissions its feed says it adds. **Update** downloads it and installs it like a hand install: new permissions aren't granted (it asks when it needs one), and **Go Back to Version X** returns to the one you had. Nothing installs by itself. If the downloaded file asks for more than its feed said, nothing is installed until you choose **Update Anyway**. An update that needs a newer app says which features are missing. Commands: `plugin.setUpdateCheck`, `plugin.checkUpdates`, `plugin.update`.
- **Remove** asks first and can keep the plug-in's data and settings.
- **About tab**: description, commands, and where the plug-in comes from: Homepage, Source Code, Changelog and Licence links, plus **Report a Problem** for a GitHub repository. Pixel filters show the same links on their page.
- **What a plug-in can add**: menu commands with dialogs, settings pages, export post-processing, export destinations ("Then send to"), publish services, metadata and keyword suggestions, custom metadata fields, programs it starts, pixel filters.
- **Commands** appear under **File ▸ Plug-ins** and run as `plugin.run`, so CLI, MCP and actions can run them too.
- **SDK**: write plug-ins in Rust with the `sdk/plugin` crate. Eight example plug-ins live in `sdk/examples` (catalog tools, batch metadata, export tools, publish folder, program tools, custom fields, job tools, keyword picker). Stamp a release build with `plugin-stamp` (`sdk/stamp`), which copies the plug-in's manifest into the `.wasm` so tools can read it without running the plug-in. `plugin-stamp sign` then signs it with the author's own key. The app checks a stamped plug-in's copy each time it installs or loads it, and refuses one whose copy doesn't match, naming what differs.
- Lightroom Lua plug-ins are not supported.
