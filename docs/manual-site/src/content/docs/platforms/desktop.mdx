## Packages
| Platform | Download |
|---|---|
| macOS | `.dmg`, one for Apple silicon (`arm64`) and one for Intel (`x64`), plus a universal one for both; not signed with an Apple developer certificate or notarised, so macOS asks you to allow it once (see [Install](../../start/install/)) |
| Windows | `.msi` installer (x64; an Arm64 build is tested in CI), and a portable zip |
| Linux | AppImage, `.deb`, `.rpm`, Flatpak bundle (not on Flathub), `.tar.gz` |
| FreeBSD | `.tar.gz`; the release job is currently disabled |
| RISC-V | not shipped |

- Linux packages install a desktop entry, file types and a camera (PTP) udev rule. AppImage and Flatpak users add the rule by hand for tethering.
- Flatpak can reach the network and the Pictures folder only; widen with a Flatpak override if you keep photos elsewhere.

## One copy at a time
- Opening the app again while it runs (its icon, a photo opened with it, an `<app>` link) brings the running copy to the front and hands it what was opened: photos and folders are imported, a link is followed. The new launch ends there.
- Starting it with an option (`--library`, `--control`, `--demo`, …), or with `<PREFIX>_NEW_INSTANCE` set, always starts a separate copy.
- **Links** (`<scheme>://sync?path=FOLDER` opens Synchronize Folder for that folder) are registered with the system by the Windows installer and by the Linux packages' desktop entry, so a script, a sync tool or a browser can open them. On macOS links are not registered yet: use `<cli> open-url` or `<cli> sync-folder` instead.

## Updates
- **Help ▸ Check for Updates…** reads the release feed, shows the notes and how long ago it last checked ("Last checked 5 minutes ago"), then **Download** fetches the file for your platform, verifies that it was signed by the Chromaforge authors, and offers to install it over this version (where the app can't install itself, it opens the file's folder instead). When the download is ready, **Install and Relaunch** is highlighted and has the keyboard focus, so Return presses it. The notes show `code`, **bold** and links as such; a link opens in your browser.
- **Help ▸ What's New** lists the changes under a heading for each date, newest first. The newest date is open; click a date's arrow, or focus it and press Space or Enter, to open or close it. Older dates are added as you scroll to them. Its text is formatted like the update notes.
- A download is installed only when the release's checksum list carries a valid signature; it is checked again before install.
- Installing an update restarts the app. On Windows the app quits, the installer runs, and the app starts again when it is done (after a restart the installer asked for, if it needs one); Start-menu shortcuts, and taskbar entries pinned from them, keep working across updates. macOS, AppImage and portable-zip copies swap the new version in and start it once the app has quit.
- **Check for updates when the app starts** is off by default (Settings ▸ General ▸ Startup). Nothing else phones home.

## Display and HDR
- **Settings ▸ Display ▸ Choose Profile…** picks a monitor ICC profile; **Use sRGB** clears it. Without one, macOS and Linux use the screen's own profile; Windows reads the profile Windows assigns.
- Previews and the Detail view use the display's gamut; exports and the histogram stay sRGB.
- Linux and Windows follow only one display's profile; per-monitor follow on Windows and pure Wayland is not built.
- **HDR display** output is partial: Settings ▸ Performance ▸ *HDR display where the screen supports it* (applies at next launch).
